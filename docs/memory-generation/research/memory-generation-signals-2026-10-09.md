## 1. 概要

### 1.1 研究问题

Agent 运行时产生的 trace（模型调用、工具调用与返回、用户消息、最终结果及评估分数）被可观测平台持久化后，库中积累了同一 agent 在大量任务上的执行记录。本报告研究如何从这些已存 trace 中有策略地批量生成记忆，供产生 trace 的 agent 在后续任务中使用，目的是避免重复错误、复用已验证做法、遵循用户偏好，场景优先 code agent 与 data agent。问题包含输入加工、选样与分组、生成方法、整合与生命周期、存储与溯源、与评估和归因的关系、偏好与 data agent 的特殊性、评测八个子问题（第 2.1 节）。

### 1.2 调研范围与方法

本报告是"基于 Agent Trace 生成记忆"调研的三份报告之一，覆盖生成所依赖的信号与选样：trace 库挖掘与近似 trace 归类（第 4 节）、失败归因与评估（第 5 节）、用户偏好与纠正（第 6 节）、data agent 的经验记忆（第 7 节），综合分析与证据边界见第 8、9 节。生成方法（论文、开源实现、产品、相邻方向）见《生成方法调研》；输入、存储与评测见《输入、存储与评测调研》。三份报告的调研过程与证据分级相同，概述如下。

调研分四个阶段，检索截至 2026-10-09（第 3 节）。第一阶段做广度覆盖，包括从轨迹生成经验记忆的论文、开源记忆组件、产品记忆机制、trace 库挖掘与失败归因、存储溯源与评测、data agent、与评估归因的耦合七个方向；第二阶段针对第一阶段的空白拓展 trace 预处理与结果判定、用户偏好、近似 trace 与选样、开源实现源码深读、评测方法五个方向；第三阶段补充 trace 标识与内容采集、生成侧模型接口两项基础事实；第四阶段回到全文与一手来源核实约 30 项被结论引用的说法，并补充相邻方向与 2026 年 7–10 月的新工作。方法包括阅读 arXiv 全文、在固定 commit 上只读源码、阅读官方文档与 changelog、在 Open-SWE-Traces 与 Who&When Pro 等公开数据集上做统计。证据分为原文或源码核实、据摘要、二手资料、未核实与公开数据统计五级（第 3.6 节），据摘要、二手资料、未核实三级在句末括注，公开数据统计注明样本与方法；与第四阶段核实结果冲突的说法按核实后的口径书写。

### 1.3 主要发现

1. 去掉具体实体的 LLM 任务抽象跨情境损失最小（未见任务上平均精度均值 MAP 下降 11.0%，其他表示 29.9%–42.5%，2511.21730）；平台侧普遍采用"逐条摘要 → 向量 → 聚类 → LLM 命名"，成本集中在逐条摘要（Clio 中占 92%）（第 4.2、4.4 节）。
2. 平台侧"聚类 → 记忆"的闭环只有 LangSmith Engine 的 Agent Overview 与 Claude Code /insights 的规则建议（后者为二手资料），二者均未公开合并算法与写入阈值；研究侧的组内对比以"同一 query / 任务"分组，尚无以近似 trace 簇分组并评估收益的工作（第 4.9 节）。
3. 对单一 agent 与模型，任务结果主要由任务本身决定：同 instance 分组中只有 12.2% 的组成败并存；放宽到同 repo 后可对比轨迹从 14.8% 增至 81.9%，新增对比大多混入难度差异，提高文本相似度只把成功率差从 0.36 降到 0.31。动作结构作为检索键几乎无用（P@1，即首位近邻与查询属于同一 repo 的比例：动作结构 0.043，文本 0.670）；阈值连通分量的可用阈值集中在 0.3 附近，簇标识跨运行不稳定（第 4.4–4.6 节、《输入、存储与评测调研》第 9.2、9.5、9.6 节）。
4. 结果信号的可靠性差异大。Open-SWE-Traces 上失败轨迹自述成功的比例（47.6%）高于成功轨迹（39.2%）；自评记忆的被信任错误比例单次静态估计为 0.28，闭环中为 0.42，更强或跨厂商的 judge 继承同一偏差，执行侧信号与检索外部信息的核验有效（2608.00017）；步骤级自动归因在长日志上为 3.5%–8.8%，接近随机基线 4.2%（Who&When）（第 5.1、5.4 节、《输入、存储与评测调研》第 9.4 节）。
5. 验证门控有独立价值：去掉门控后 EDGE 为 72.3，低于不用经验的 82.1；OpsHarness 末段 0.33，低于不演化的 0.43；Crystallization 无门控的卡片库比无记忆低 2.03 个百分点（第 5.4、7.7 节、《生成方法调研》第 4.7 节）。
6. 结果级成败是现有学术方案的主信号，其误差可被分组对比与效用计数部分吸收；步骤级归因的误差大到不能单条直接写入记忆；评估平台的数据结构能承载 trace 级 outcome，承载不了归因结果的完整形态；评估、归因与记忆生成的耦合有三种递进模式，后两种都以 trace 级 outcome 可用为前提（第 5.7、5.8 节）。
7. 一次性主张被写成偏好会传播：PASB 中主张被写入记忆的运行后续失败率 71.9%，未写入为 45.0%（观察分组），被写入的主张 33.1% 丢失来源；把偏好编译为工具调用前后的校验比注入上下文合规率高 15 个百分点（TRACE，70.1% 对 55.0%）；撤销只在存储层标记时旧值仍被沿用（第 6.3、6.6、6.7 节、《输入、存储与评测调研》第 7.7 节）。
8. data agent 的记忆以数据库为作用域，执行验证是主要增益来源：Crystallization 中门控贡献 4.85 个百分点、本库卡片（来自同一数据库）比外库卡片（来自其他数据库）高 6.73 个百分点；公开基准标注错误率高（BIRD Mini-Dev 52.8%、Spider 2.0-Snow 公开 gold 62.8%）；产品侧的指标口径与业务规则类知识均经人工审核后生效（第 7 节）。

### 1.4 主要倾向

下表为现有证据下更可取的做法及其适用条件，依据与证据强度见第 8 节。本表只列与本报告主题相关的环节。

表 1-1 主要倾向及其适用条件

| 环节 | 更可取的做法 | 适用条件 |
|---|---|---|
| 选样 | 以外部验证、用户反馈、执行证据为结果信号，agent 自述不作信号；优先同组成败并存与失败后恢复的 trace；成功轨迹用于程序类记忆，含失败的组用于经验类记忆；无结果信号的 trace 用于偏好与环境事实 | 存在可信的 trace 级 outcome；judge 只在具备执行能力且输入去除自述时使用 |
| 分组 | 成败对比限定在同任务、同一决策点或首个分歧步之后；近似任务层改为同向归纳（成功流程只从成功轨迹中归纳，失败模式只从失败轨迹中归纳），结论需多对支持；分组在仓库、数据库等元数据作用域内进行，任务表示采用去实体的 LLM 抽象 | 同任务有多次执行；簇作为派生索引，稳定性需监控 |
| 验证 | 新条目先处于候选状态，经环境只读核验、历史 trace 重放不退化或留出集对照后生效；data agent 以执行结果门控；操作级质量分只用于过滤 | 有只读环境、可重放环境或留出集；验证成本可占预算的一半 |

### 1.5 主要开放问题

- 每个簇送多少条 trace 做归纳、预算如何在簇之间分配，缺少收益曲线。
- 同任务对比与近似任务对比未在同一实验中比较；跨任务对比时任务难度差异混入成败对比（难度混杂，confounding），缺少公认的校正方法。
- 无标签 trace 上 judge 误差对记忆质量的影响，以及纯离线 trace 库上三类门控方式的效果比较，缺少实证。
- data agent 缺少带真实用户纠正的公开轨迹，指标口径类记忆缺少评测。

## 2. 问题与术语

### 2.1 研究问题

Agent 运行时产生 trace：用户消息、模型调用、工具调用及其返回、最终结果，以及关联到这些对象的评估分数。trace 平台把它们持久化后，库中积累了同一 agent 在大量任务上的执行记录。本报告研究的问题是：从已存的 agent trace 中有策略地批量生成记忆，供产生这些 trace 的 agent 在后续任务中使用。记忆服务于三个目的：避免重复已经出现过的错误；复用已经验证有效的做法；遵循用户表达过的偏好与约定。场景上优先 code agent（修复 issue、实现功能、运行测试）与 data agent（text-to-SQL、数据分析、数据整理），两者的结果都可以通过执行（测试、查询结果）验证，且都有公开的执行轨迹数据（《输入、存储与评测调研》第 9 节）。

问题的限定如下：

- **输入为已存 trace**。生成在 agent 运行之外的后台或离线流程中进行，可以跨会话、跨任务观察。会话内由主 agent 即时写入记忆的做法（如 GitHub Copilot 的 `store_memory`、Claude Code auto memory，《生成方法调研》第 6 节）作为对照。
- **有策略**。库中 trace 的数量远超可逐条调用模型的预算，需要决定哪些 trace 进入生成（选样）、按什么单位做对比与归纳（分组），以及预算如何分配。
- **批量**。生成以批为单位运行，包含逐条 trace 的抽取与跨 trace 的整合，需要处理增量、去重、冲突与淘汰。
- **使用方为同一 agent**。记忆以文本可读的条目注入该 agent 的上下文。把经验固化进模型权重属于相邻方向（《生成方法调研》第 7 节）。

该问题可拆分为以下子问题：

| 选样与分组 | 选取哪些 trace；同任务与近似任务分组；预算分配 | 第 4 节、《生成方法调研》第 4 节、《输入、存储与评测调研》第 9 节 |

### 2.2 术语

下表只列本报告用到的术语；完整术语表、综述分类法对照与本调研使用的记忆分类见《生成方法调研》第 2.2–2.4 节。

表 2-2 术语

| 术语 | 定义 |
|---|---|
| 记忆（memory） | 从历史执行中生成、持久保存、在后续任务中注入 agent 上下文的文本条目。本报告的记忆指跨任务持久的外置记忆；单次任务内的上下文与 scratchpad（工作记忆）以及模型权重不在此列 |
| trace / span | 采用 OpenTelemetry（OTel）的定义。trace 是一次端到端执行，由若干 span 组成树；span 是其中的一次操作，带 `trace_id`、`span_id`、`parent_span_id`、起止时间、状态与属性。OTel GenAI 语义约定把 agent 的操作区分为 `invoke_agent`、`chat`（一次模型调用）、`execute_tool` 等。Langfuse 中对应的对象为 trace 与 observation |
| 会话（session） | 同一用户与 agent 的一段连续交互，可包含多个 trace；OTel 中以 `gen_ai.conversation.id` 或 `session.id` 标识 |
| 经验记忆（experiential memory） | 从执行结果中总结的教训与策略，例如某类失败的原因与预防方法、失败后的恢复步骤、较优的处理方式。术语取自 Hu 等（2512.13564） |
| 偏好记忆 | 用户表达的、跨任务成立的要求与约定，例如代码风格、提交流程、输出格式、指标口径。信号主要来自用户消息中的纠正、明确要求与拒绝 |
| 程序性记忆（procedural memory） | 可按步骤执行的流程，例如工作流、SOP、技能文件（`SKILL.md`）、可复用脚本与已验证查询模板 |
| outcome | trace 或任务级的结果标签，例如单元测试判定的 resolved、环境 reward、评估分数、用户确认 |
| 信号来源类别（signal source type） | outcome 的来源类别：ground truth 或测试、执行信号（退出码、报错、空结果）、用户反馈、LLM judge、agent 自述。不同类别的可信度不同，同一 outcome 需要记录其来源类别 |
| 失败归因（failure attribution） | 在失败 trace 中定位出错的 agent、步骤与错误类型；结果可作为生成预防类记忆的输入（第 5 节） |
| 溯源（provenance） | 记忆与其来源之间的可回溯关系：来源 trace / span、派生自哪些已有记忆、由哪一次生成运行产生。用途包括回源校验（回到来源内容核对记忆是否仍成立）、安全门控（按来源可信度过滤）与价值归因（《输入、存储与评测调研》第 7 节） |
| 成败并存 | 同一分组（如同一任务的多次执行）内同时有成功与失败的 trace，是做成败对比的前提 |
| 难度混杂（confounding） | 跨任务比较成功与失败轨迹时，任务本身的难度差异混入对比，对比得到的差异同时反映难度与 agent 行为 |
| 自述成功 | agent 在最后的输出中自称任务完成或成功，未经外部判定 |
| 晋升（升格） | 候选条目达到写入门槛后成为生效记忆，或从一种载体提升到更持久、作用范围更大的载体（如从可检索条目到技能文件） |
| 选样（selection） | 决定哪些 trace 进入生成，依据包括 outcome、是否同组成败并存、是否为失败后恢复、新颖度与预算 |
| 分组（grouping） | 把 trace 组织为对比或归纳的单位，例如同一任务、同一仓库或数据库、近似 trace 簇 |
| 整合（consolidation） | 把候选记忆并入已有记忆库：去重、合并、冲突消解、按支持频次保留、以增量操作（ADD、UPDATE、DELETE 等）更新 |
| 注入（injection） | 记忆进入 agent 上下文的方式：每次会话常驻加载的小体量条目、按任务相似度检索的条目、由 agent 通过工具按需读取的条目 |
| 个百分点（pp） | 两个百分比之间的差值单位。正文写"个百分点"，表格内简写为 pp；"%"只用于比例本身或相对变化 |
| GT | ground truth，标准答案或测试判定的真实结果 |
| harness / scaffold | 包裹模型的 agent 运行框架，含系统提示、工具定义、上下文管理与执行循环 |

### 3.2 第一阶段：广度调研

**方向 4：trace 库挖掘、聚类与失败归因。** 要回答的问题：可观测平台与研究工作如何对 trace 库做批量摘要、聚类、命名与失败归因，以及多条 trace 如何归纳为记忆。检索范围为 25 项，包括 Anthropic Clio、Braintrust Topics、PostHog LLM Clusters、LangSmith Insights 与 Engine、Datadog LLM Observability Patterns、Transluce Docent、Langfuse，失败归因方向的 Who&When、TRAIL、MAST，以及 trace 表示与相似度研究。方法为阅读平台官方文档与博客、论文正文或摘要页。发现：平台普遍采用"逐条 LLM 摘要 → embedding → 聚类 → LLM 命名"；成本集中在逐条摘要（Clio 每 10 万条对话约 48.81 美元，其中 92% 为 facet 抽取，2412.13678；facet 指按预设维度从每条对话抽取的属性，如主题、语言、请求类型）；工具序列等结构相似度只出现在研究中，span 树结构未被用于聚类；研究侧的组内对比只按"同一任务"分组。详见第 4 节。

**方向 6：data agent 的经验记忆。** 要回答的问题：text-to-SQL、数据分析、数据科学、数据整理 agent 如何从执行轨迹或用户反馈沉淀记忆，与 code agent 的记忆内容有何差异，有哪些公开数据集与评测设置。检索范围包括 Crystallization（2608.07213）、Tk-Boost（2602.13521）等论文，Snowflake Cortex Analyst、Databricks Genie、Wren AI 等产品，以及 HF 上的轨迹与交互数据集。方法为阅读论文正文、产品文档，并下载或通过数据卡核对数据集字段。发现：data agent 记忆以数据库或语义模型为作用域；执行验证门控本身是增益来源（Crystallization 中门控贡献 4.85 个百分点，不经外部验证、只由模型自投票决定入库的卡片库比无记忆低 2.03 个百分点）；产品侧的指标口径与业务规则类知识均经人工审核后生效；评测集标注错误会影响以 gold 为信号的选样（2601.08778）。详见第 7 节。

**方向 7：记忆生成与评估、归因的耦合。** 要回答的问题：现有 trace→记忆方案如何依赖成败信号与失败归因，记忆系统能反向产出哪些评估信号，评估与归因结果的数据形态是什么。检索范围为论文、产品，以及 OTel `gen_ai.evaluation.result` 事件、Langfuse scores、Phoenix、MLflow、LangSmith 的评估结果结构。方法包括逐字段核对 OTel GenAI 语义约定与 Langfuse 源码中的表定义。发现：信号依赖分为五类（不需要成败、结果级成败、LLM judge 自评、步骤级归因、人工或用户反馈）；步骤级归因在现有方案中几乎都在生成记忆的同一次 LLM 调用内部完成，未检索到持久记忆流水线消费独立归因模块结构化输出的公开工作；OTel 已定义 `gen_ai.memory.client` span 与 `gen_ai.memory.record.id`，可作为记忆使用与评估分数之间的关联键。详见第 5 节。

### 3.3 第二阶段：拓展与聚焦

**方向 2：用户偏好与纠正挖掘。** 由第一阶段产品调研引出：产品把用户纠正列为最高价值信号，而偏好与经验在写入门槛和作用域上不同。要回答的问题：如何识别偏好与纠正信号，如何区分偏好与一次性指令，写入门槛、作用域、冲突与漂移如何处理，如何评测，有哪些数据。检索范围包括研究论文、十余个产品的写入规则（Claude Code、Codex、Copilot、ChatGPT、Kiro、Augment、Devin、Databricks Genie、Snowflake Cortex Analyst、Hex、Cursor Bugbot 等）、偏好基准与含纠正信号的会话数据集。方法为阅读论文、官方文档、官方仓库源码与已发布安装包中的内嵌提示词，数据集通过 HF 数据卡与 API 核对字段。发现：个人偏好普遍为"自动写入 + 事后可查可删"，共享知识普遍为"建议 + 有权限者确认"；升格门槛分为单次明确纠正即存与要求跨任务重复两种做法；PASB（2607.10526）中，51.4% 的运行中 agent 把用户主张写入记忆并改写为稳定偏好、背景事实或流程，被写入的条目有 33.1% 丢失来源；主张被写入的运行，后续新对话的判定失败率为 71.9%，未写入的运行为 45.0%（观察分组、LLM judge 判定）。详见第 6 节。

**方向 3：近似 trace 判定、分组归纳与选样。** 由第一阶段的空白引出：没有从已存 trace 中选样的系统策略；组内对比只按同一任务分组；簇标识跨运行的稳定性缺少方案。要回答的问题：如何给 trace 生成可比较的任务表示；在近似任务上做组内对比归纳是否有效；聚类如何增量运行并保持簇标识稳定；大规模库中选哪些 trace 与簇做归纳。方法为文献阅读加 Open-SWE-Traces 上的实验：比较文本相似度与动作结构相似度的区分度、检索命中率与结果预测能力，统计阈值连通分量中单链接的链式效应（chaining）与跨任务对比中的难度混杂。发现：去掉具体对象的 LLM 抽象在未见任务上损失最小（2511.21730 中 MAP 下降 11.0%，其他表示下降 29.9%–42.5%）；动作结构作为检索键几乎无用，结果主要由任务本身决定；阈值连通分量的可用阈值集中在 0.3 附近；把对比从同任务放宽到同仓库后，新增对比大多混入任务难度差异。详见第 4 节、《输入、存储与评测调研》第 9 节。

### 3.4 第四阶段：补充

**方向 1：可信度核实。** 要回答的问题：被结论引用、但前三阶段只据摘要或二手资料的说法是否成立。范围为 26 组、约 30 项说法，覆盖失败归因准确率、记忆判定误差、偏好写入风险、编码记忆基准、簇稳定性阈值、产品记忆机制、开源框架行为、trace 平台规模、生成 prompt 的公开情况、评测标签误差、注入防护、模型 API。方法为回到 arXiv HTML 全文或 PDF、官方文档与 changelog、固定 commit 的源码，判定为"确认""更正""无法核实"三类，并对可复算的数字做复算。关键更正举例：Who&When（2505.00212）的 agent 级 53.5% 与 step 级 14.2% 来自两种不同方法、为四个设置的平均，长日志手工系统上 step 级只有 3.5%–8.8%，接近随机基线 4.2%；AgenTracer（2509.03312）"至多高 18.18%"无法从正文表格复算，表中最大绝对差为 17.4 个百分点；PASB 的两组为观察分组；VibeMemBench（2609.23570）直接注入的 1.1–4.5 个百分点增益置信区间均跨零，且目标按"注入经验有效"筛选；Claude Code Auto Dream 在官方文档与 changelog 中不存在，只能作为第三方逆向描述；Cursor Memories 已于 2.1.x 移除；LangSmith Engine 截至 2026-09-24 分析超过 7000 万条 trace；Raindrop 的官方描述为按描述训练的小模型分类器，与 embedding 聚类属于不同路线；Mem0 2.x 的开源写入只做 ADD。无法核实的项为 Claude Code Auto Dream 的细节与 ChatGPT 偏好遵循 71.3% 的官方出处。凡与核实结果冲突的说法，本报告以核实结果为准。

## 4. trace 库挖掘与近似 trace 归类

本节讨论在已存 trace 库上做批量挖掘的方法，覆盖六个问题：可观测平台如何对大量 trace 做归类与问题发现；挖掘的成本分布；trace 用什么表示、相似度如何定义；"近似任务"的判定与组内对比归纳的有效性；聚类结果如何增量维护并保持簇标识稳定；在有限预算下选哪些 trace 做归纳。从轨迹生成经验记忆的论文本身见《生成方法调研》第 4 节，过程挖掘与 AIOps 的完整调研见《生成方法调研》第 7 节，公开数据集上的统计细节见《输入、存储与评测调研》第 9 节。

本节术语：facet 指按预设维度从每条对话或 trace 抽取的属性（如任务、情绪、问题）；UMAP（Uniform Manifold Approximation and Projection）为非线性降维方法；HDBSCAN 为基于密度的层次聚类算法，不需预设簇数，把不属于任何簇的点标为离群点。

### 4.1 平台与工具的做法

各项的机制与参数如下。

**Clio（2412.13678）。** facet 文本用 all-mpnet-base-v2（768 维）嵌入，k-means 聚类，k 随对话数变化且未公开。簇命名用 Claude 3.5 Sonnet（温度 1），输入为簇内 50 条摘要与簇外最近质心的 50 条对比摘要。层次构建逐层进行：对簇名与描述做 embedding，用 k-means 划出平均约 40 个簇的"邻域"，在邻域内由模型提议上层簇（附邻域外最近的若干簇作对照），跨邻域去重，把下层簇分配到父簇，再重写父簇名称；示例为 10 → 100 → 1000 三层。隐私控制分四层：摘要去隐私、簇最小唯一账户数阈值、簇摘要去隐私、模型审计。合成数据上重建分类准确率 94%。

**Braintrust。** 官方文档描述 Topics 为每日流水线：预处理 → facet 摘要（持续生成）→ 聚类与命名（每日，至少需要 100 条摘要）→ 新 trace 分类到已有主题；三次模型调用分别用于 facet 摘要、embedding 与簇命名，内置 facet 为 Task、Sentiment、Issues，支持自定义 facet prompt 与预处理函数。文档只写"a clustering algorithm"，具体算法"BERTopic 风格，UMAP 降维 + HDBSCAN + c-TF-IDF"出自 2026-02 的官方博客。主题重跑会替换现有主题。Patterns 作为定时自动化运行：保存前对照代码仓库核验原因与修复，区分"已确认原因"与"假设"；每次运行更新已有 pattern 的证据与频次，只在近期数据支持时关闭 pattern；pattern 可转为 facet、scorer、分类器或监控。官方把 Topics 定位为低成本全量分类层，Patterns 为子集深度调查层。

**PostHog。** 渲染为带行号（`L001:`）的 ASCII 树，超长 trace 均匀下采样：保留头部，每隔 N 行保留一行并注明显示比例，行号断档表示省略。摘要由 GPT-4.1 nano 结构化输出，要点带行号引用。去掉行号后用 text-embedding-3-large（3072 维）嵌入，UMAP（cosine）降到 100 维用于聚类（min_dist=0.0），另降到 2 维用于展示；HDBSCAN 取 min_cluster_size=5、eom 选簇，离群点标为 −1。命名由 GPT-5.2 驱动的 LangGraph ReAct agent 完成：8 个工具，先为全部簇生成标签保证覆盖，再对含糊簇下钻 trace，最后调用 `finalize_labels`。结果以 `$ai_trace_summary`、`$ai_trace_clusters` 等事件写回；每小时随机采样子集，Temporal 每日调度，最多 4 个并发子流程。

**LangSmith Insights。** 摘要模型与聚类模型分开配置；样本上限 1000 条 trace；可抽取 string / numeric / boolean 属性，boolean 属性可作为预过滤；摘要 prompt 可引用 run 的输入、输出、错误、反馈或整段线程消息。可只给顶层类别，子类自动生成；未预设类别时，首次发现的类别存回配置，供定时任务复用。

**LangSmith Engine。** 先读压缩轨迹视图（每轮一行：role、工具名、延迟、内容字符数，不含正文），仅在深查时加载全量；带人工标注、judge 分数或点赞点踩的 trace 优先分诊。Haiku 驱动的筛查子 agent 每次看约 20 条 trace、多路并行，只输出"trace ID、类别、理由"一行；调查子 agent 拉取全量 trace 与代码，判断是否真实问题、是否归入已有 issue。Issue Board 含已关闭 issue，新证据追加到已有 issue；匹配机制未公开，未使用 embedding 聚类；类别来自预定义失败模式表（`pii_leak`、`agent_looping`、`incorrect_tool_args`、`missing_tool` 等）。每个 issue 生成代码或 LLM-judge 评估器，在证据 trace 上迭代到命中，并为证据 trace 生成回归样例。Agent Overview 由引导问答与首轮分析生成，后续运行读取并更新。截至 2026-09-24，官方称已分析超过 7000 万条 trace；v2 增加 Red Teaming（private beta）、低效路径检测（错误或重复的工具调用）与性能趋势监测。

**Datadog Patterns。** 每条交互只属于一个主题，离群点单独成组并计入"Classified"比例。单次上限 10,000 span 或 5,000 trace，超出部分随机采样，运行约 5–10 分钟，可按日或周调度。每次运行为覆盖不足的主题向 `{pattern-name}-pattern-curated` 数据集追加建议样例（默认开启）；两次运行可对比主题分布，新主题标 NEW。

**Docent。** 先抽取"每条 transcript 如何匹配查询"的短文本，大模型提议初始中心，小模型分配，再用启发式调整互斥与完备，不依赖 embedding。Analysis Plans 交替执行 DQL 步骤（确定性的过滤、分组、聚合）与 Reading 步骤（每行一次 LLM 调用），`array_agg` 可把多行合并为一次调用；可在头部类别内递归再聚类，上一步的簇名可作为下一步输出 schema 的 enum；步骤按内容寻址缓存，重跑只执行变更步骤。

在 Open-SWE-Traces 单一 agent / 模型子集上的统计（《输入、存储与评测调研》第 9.5 节）得到一致的方向：以动作 bigram 做近邻检索，命中同 repo 的比例为 4.3%，issue 文本为 67.0%；同一任务内成功-成功对与成功-失败对的动作相似度可分性 AUC 只有 0.563；同 repo 其他任务的成功率预测结果的 AUC 为 0.707，高于任何相似近邻。

**MONIC 规则。** overlap 按记录年龄加权：overlap(X, Y) = Σ_{a∈X∩Y} age(a) / Σ_{x∈X} age(x)，权重相等时为 |X∩Y| / |X|。旧簇 X 的 match 取 overlap 最大且 ≥ τ 的新簇，τ ∈ [0.5, 1]；匹配到的新簇不同时是其他旧簇的 match 为存活，同时是则为吸收；拆分只在 X 无 match 时判定，要求各部分 ≥ τ_split、并集 ≥ τ，且 τ_split < τ；以上均不成立为消失；无来源的新簇为新生。论文实验取 τ = 0.45–0.7、τ_split = 0.1–0.35，主分析用 0.5 / 0.1；clusTransition 默认 `Survival_thrHold` = 0.7、`Split_thrHold` = 0.3，使用不加权的 overlap。

**Drain3 参数。** `sim_th` 默认 0.4（相同 token 比例低于该值则新建簇），`depth` 默认 4，`max_children` 默认 100，`max_clusters` 默认不限，达到上限后按 LRU 淘汰；支持正则掩码；快照含搜索树、簇、簇大小与簇 ID，后端可为 Kafka、Redis、文件或内存。该方法适用于错误消息、工具调用签名等可模板化的字段。

**稳定性度量。** 簇级 bootstrap Jaccard（Hennig，`fpc::clusterboot`，默认 B = 100）：均值 ≥ 0.75 为稳定，≥ 0.85 为高度稳定，0.6–0.75 表示数据中有模式但成员归属不确定，< 0.6 不可信；单次 Jaccard ≤ 0.5 记为该簇"解散"。文档同时指出稳定不等于有效，刚性算法也能产生稳定但无意义的簇。

**阈值连通分量的链式效应。** 在 Open-SWE-Traces 任务文本 TF-IDF 的 kNN 图上按相似度阈值取连通分量（《输入、存储与评测调研》第 9.6 节）：阈值 0.2 时出现覆盖 41% 任务的单个超大连通分量，repo 纯度 0.38；阈值 0.3 时该超大分量消失、纯度 0.91，覆盖率由阈值 0.2 时的 70.1% 降到 37.6%；阈值 0.4 时覆盖 18.4%，0.5 时覆盖 8.5%。阈值连通分量等价于单链接聚类，存在链式效应（chaining，相似度逐对传递使不相似的成员连入同一分量），可用阈值集中在 0.3 附近，阈值变化时大量分量合并或拆分。

簇变更时派生记忆如何迁移，检索范围内未见公开方案：Braintrust 重跑即替换，LangSmith Insights 只固化类别。可用于这一问题的现有做法有三项：MONIC 以成员重叠判定簇的存活、吸收、拆分、消失与新生，适用于周期重聚类；bootstrap Jaccard 度量单个簇的稳定性；Drain3 对可模板化字段给出不随重跑改变的簇 ID。调研倾向（推论）：记忆以证据 trace 集合为依据，簇只作为派生索引，不稳定的簇不作为归纳单元。

大批量聚合有已知的退化。Combee（2604.04247）把 ACE 的批大小从 1 提到 100 时，Formula 准确率 87.0% → 72.5%，playbook 更新数 264 → 21，全部反思都在 128K 窗口内，退化来自聚合器把大量反思压成少量泛化条目；按约 √n 的 mini-batch 层次合并、每条反思复制两份打乱可缓解。Zalando 报告表层归因错误（把仅被提到的技术当成原因）在 Claude Sonnet 4 下仍约 10%，数值字段抽取不可靠，改为从结构化数据读取。

各来源的 prompt 要点：摘要要求引用行号或 span ID；失败备注只记第一个失败点（上游错误常引发多个下游错误）；归纳去掉站点、实体等具体值并限制每条轨迹的条目数（ReasoningBank 为 3）；合并时冲突优先成功轨迹与恢复经验，区分"已确认原因"与"假设"。

### 4.9 小结与空白

平台侧已形成稳定的流水线：渲染 → 逐条 facet 摘要 → 向量 → UMAP + HDBSCAN 或 LLM 归类 → LLM 命名，摘要占成本主体，结果写回 trace 字段并保留回指。平台侧"聚类 → 记忆"的闭环只有 LangSmith Engine 的 Agent Overview 与 Claude Code /insights 的规则建议（后者为二手资料），二者均未公开合并算法与写入阈值。

研究侧的组内对比以"同一 query / 任务"分组，尚无以近似 trace 簇分组并评估收益的工作；跨任务对比存在可量化的难度混杂，过程挖掘中"同一决策点 / 首个分歧步"的局部对比是现有的缓解形态。

主要空白：span 树结构未用于 agent trace 聚类；簇标识跨运行的稳定性与簇变更时记忆迁移缺少公开方案；每簇归纳样本量的收益曲线缺失；trace 挖掘产出记忆的效果评估集中在 AppWorld、WebArena 等基准，缺少生产 trace 库上的对照数据。

## 5. 失败归因、评估与记忆的关联

本节讨论三件事：失败归因方法能给出什么精度与什么形态的结果；现有记忆方案依赖哪类成败信号、信号在哪一步进入流水线、判定误差有何影响；评估平台的结果数据形态能否承载记忆生成所需的信息。

| EvolveR / ReMe / MemRL | 被检索次数与成功次数、Q 值 | 任务结果回写 | 剪除、重排 |
| EDGE | 组内带与不带经验 rollout 的回报差 Δe 的 EMA | 组内一半 rollout 注入经验 | Δe < −0.1 剪除 |
| OPD-Evolver（2606.17628） | 同组"被检索且选中"与"被检索未选中"的平均回报差 × 置信因子 | 使用日志 | 维护阶段删改 |
| EvoSOP | SOP 调用标为 Optimal / Partial / Neutral / Negative / Defect | Reviewer | 剪枝 |
| MemQ（2605.08374） | 沿溯源 DAG 的 TD(λ) 信用 | 使用与派生链 | 价值学习 |
| MemTrace（2605.28732） | 把记忆系统失败归因到具体记忆操作 | 记忆演化图追踪 | 指导 prompt 优化（据摘要） |

信用分配有两个已知问题：同时检索的记忆共享轨迹级回报（RoMeRL）；自评回报随复用膨胀（2608.00017）。EDGE 与 OPD-Evolver 用"同组有 / 无该记忆"的对照缓解，前提是同任务有多次执行。另一项相关结果：自演化技能的反馈对照实验（2608.02636）中，被选中的 11 次更新全部来自含失败轨迹的反馈（据摘要）。

平台与研究使用同一类中间对象：平台侧方向是"失败簇 → 评估器 / 数据集"（LangSmith Engine 生成评估器与回归样例，Datadog 补充 curated dataset，MLflow 把代表样例放入评估集，Braintrust 把 pattern 转为 scorer），研究侧方向是"结果 → 记忆 → 记忆效用"；二者共享"带证据 trace 列表的失败模式"。

### 5.8 结论与倾向

结论：结果级成败是现有学术方案的主信号，其误差可被分组对比与效用计数部分吸收；步骤级归因的误差大到不能单条直接写入记忆；自评与记忆复用存在正反馈，独立来源与执行侧信号是有效的校正手段；评估平台的数据结构能承载 trace 级 outcome，承载不了归因结果的完整形态。

现有工作的相关做法及适用条件如下。outcome 的来源类别：Langfuse、Phoenix、MLflow 均以来源字段区分人工、LLM 与代码评估（表 5-8），2608.00017 显示自评与外部信号同源时误差随复用放大，因此 outcome 需要连同来源类别一起使用，自评结果需单独标记（推论）。归因结果：SkillBoost 与 IBM 2603.10600 把首个错误位置作为生成 prompt 的证据窗口，SkillBoost 与 SearchOS-V1 以多条 trace 的复现作为写入条件；单条归因准确率低（第 5.1 节），这一做法适用于同类失败多次出现的场景。使用记录：Codex 以回答中的引用回写使用计数，OPD-Evolver 区分"被检索且选中"与"被检索未选中"计算效用，前提是记忆注入在 trace 中可观测（《输入、存储与评测调研》第 5.2 节）。

## 6. 用户偏好与纠正

偏好与纠正类记忆记录用户对 agent 工作方式的要求，例如"提交前先跑 lint""回复不要附尾部总结""活跃用户口径排除服务账号"。它的证据来自 trace 中的用户消息 span（纠正、确认、显式要求、中断、拒绝）以及用户对 agent 产物的改写，判断依据是用户的话本身，与《生成方法调研》第 4 节的经验记忆依赖任务成败标签不同。本节依次整理研究工作、信号类型、写入门槛、作用域、冲突与撤销、执行方式、评测基准与数据集。

### 6.2 信号类型与识别

综合 SWE-chat、WildFeedback、Naturally Occurring Feedback、Codex 与 Claude Code 的抽取提示词，用户侧信号可归为七类：

表 6-2 用户侧信号类型

| 类型 | 典型表现 | 识别方式 | 已报告的识别精度 | 可产出的内容 |
|---|---|---|---|---|
| 显式偏好 | "always / never / 以后都 / I prefer / 默认用 X" | 关键词召回 + LLM 分类 | 未见精度报告 | 偏好条目 |
| 带内容的纠正 | 补充信息、纠正误解、改变方向，并给出具体修正 | LLM 分类，输入需含前序 agent 动作 | SWE-chat 4 类 0.67 / 二分类 0.79 | 纠正条目，附触发情境 |
| 确认 | 对不常规做法的明确认可，或未推回地接受 | LLM 分类 | 无公开数字 | 正向条目 |
| 无内容否定 | 中断、工具调用被拒、"undo that""no"、thumbs down | 规则匹配日志标记或评分表 | 规则识别为确定性结果 | 佐证，需与紧随的用户消息配对后才有内容 |
| 重做与重述 | 同一请求重复、反复收窄 | 相邻用户消息相似度 + LLM | 重述类精度 0.17（2407.10944） | 佐证 |
| 失败报告 | "测试挂了""报错了" | LLM 分类，结合工具 span 状态 | SWE-chat Failure report 类 | 经验记忆的结果信号 |
| 隐式编辑 | agent 产物被用户随后改写（代码、SQL、文档） | agent 输出与后续提交的 diff | CIPHER、SWE-chat 行级归属 | 推断类偏好 |

识别方面的事实：

1. 确定性标记可先于 LLM 分类处理。Claude Code 原始日志中，中断以用户文本 `[Request interrupted by user]` 与 `[Request interrupted by user for tool use]` 出现，拒绝工具调用以 tool_result 文本 "The user doesn't want to proceed with this tool use…" 出现，运行中插话记录为 `queue-operation` 条目（trace-commons/agent-traces 样本）。SWE-chat 另有 `queue_op_subtype` 字段区分插话的入队、送达与丢弃。
2. Codex 第一阶段提示词规定推断偏好时"用户消息的权重远高于助手消息"，用户请求、纠正、中断、重做与反复收窄为主要证据；用户需要重复同一指令或纠正时视为高信号；被用户丢弃或要求重做的产物不能视为成功（`stage_one_system.md`）。
3. 只记录纠正会造成偏移。Claude Code 的 feedback 记忆提示词要求同时记录纠正与确认（"yes exactly"、未推回地接受不常规的选择），理由是只记纠正会让 agent 偏离用户已认可的做法并趋于保守（Claude Code 2.1.263 安装包内嵌提示词，与 Piebald-AI 镜像逐字一致）。
4. 隐式行为信号易引入偏差：BlenderBot 部署数据中以后续回复长度为奖励使生成更具争议（2307.14117，据摘要）；把补全接受率直接作为奖励会降低建议质量（2306.04930，二手资料）；接受率比长期留存更能预测主观生产力（2205.06537，据摘要）。
5. 需排除的内容：助手提议、讨论中的假设、用户转述的第三方内容（PersonaMem-v2 把假设性提问与第三方撰写的消息列为不应视作用户偏好的歧义样本）、工具输出与网页内容中的祈使句，以及只对当前任务有意义的参数（文件名、本次阈值）。

### 6.3 偏好与一次性指令的区分与措辞校准

PASB（2607.10526）给出了把一次性主张写成持久记忆的后果。实验含 100 个基础条目 × 4 种场景 × 4 种主张呈现方式共 1,600 个任务，在 Hermes-Agent 与 OpenClaw 两个框架、12 个模型上运行。每个任务先进行含用户主张的首轮会话，再开一个中立的新会话提 3 个后续问题。主要事实如下：

- 51.4% 的运行中 agent 把用户主张写入记忆，并改写为稳定偏好、背景事实或可复用流程；被写入的条目有 33.1% 丢失来源。
- 按首轮会话后的状态分组：主张被写入用户画像、记忆文件或 skill 的运行，后续新会话的判定失败率为 71.9%；主张只留在首轮会话的运行为 45.0%。两组由 agent 自行决定是否写入，属于观察分组；失败率由 LLM judge（Kimi-K2.6）按四个指标判定，未写入组的 45.0% 说明该口径基线较高。
- 24 个模型-框架组合在 Sycophancy 指标上全部偏向已保存的主张，差距 +12.4 至 +58.6 个百分点；在不同领域的后续问题上 Leak、Upgrade、Sycophancy 分别高 22.8、21.4、21.2 个百分点。
- 显式记忆编辑把同领域失败率降到 32.7%（Hermes-Agent）与 54.5%（OpenClaw）；会话中纠正两轮后 Hermes-Agent 降到 40.6%，OpenClaw 五轮后仍为 64.9%。

Remember, Verify, or Ask?（2608.19564）把写入决策形式化为"持久保存 / 仅当前上下文 / 对外核验 / 向用户澄清"四选一，140 个场景的标注一致性 κ=0.962。Qwen 裸模型在 12 个应澄清项上从不澄清，few-shot 后澄清召回仍只有 0.333（据摘要）。LifeFuse-Mem（2609.12436）按"时间承诺"分离稳定与临时信息（据摘要）。PrefDisco 显示个性化本身也有副作用：29.0% 的模型-任务组合个性化后不如通用回答，模型平均只提 1.42–1.48 个澄清问题。

|---|---|---|
| Codex v2 | 用户说 "show me the plan before editing this"，只能记为 "the user asked to show a plan before editing"；用户说 "I prefer you to show plans before editing" 时才记为 "explicitly stated"；不得声称超出证据的稳定偏好或用户认可；同一任务内后到的纠正覆盖先前说法 | `stage_one_system_v2.md` |
| Codex v1 | 偏好句式 "when \<situation\>, the user asked / corrected: \"\<short quote\>\" -> \<future default\>"，反例 "the user prefers better validation"；保留用户原话；不把一次性印象与助手提议写成持久记忆 | `stage_one_system.md`、`consolidation.md` |
| Claude Code | feedback 条目先写规则，再写 **Why:**（用户给出的原因）与 **How to apply:**（何时何处适用）；范围限定靠措辞承载，例如 "for refactors in this area, user prefers one bundled PR"；可从代码库推出的约定、调试修复配方、只在本次会话有效的任务细节不保存，用户要求保存这类内容时改问其中哪部分出人意料 | 内嵌提示词 |
| Copilot Memory | 用户偏好为 "stated or implied preferences"，引用可含用户原话，由模型判断偏好是否仍适用 | 官方文档 |

这些规则的共同点是：区分"用户明确表述"与"推断"，保留原话，把适用条件写进条目。PASB 中 33.1% 的来源丢失与跨领域传播，是要求偏好条目保留原话与来源的直接依据。

### 6.7 编译为校验与上下文注入

TRACE 把"记忆系统能读到纠正但不遵守"称为 access-compliance gap。偏好检查的合规率：Mem0 42.5%（57.5% 被违反）、注入全部规则 55.0%、只注入相关规则 54.0%、编译为 hook 中的校验器 70.1%。校验分三类：确定性检查（工具调用、命令参数、文件名、工作区状态，例如 PreToolUse 中的正则）、语义检查（模型判定）与意图级提醒。规则生成时经过 JSON 解析、schema、单元测试、沙箱回放四阶段自校验。在 ClawArena 上违反率分布内由 100% 降到 37.6%、分布外降到 2.0%。

注入侧的证据：PrefEval 中 Claude 3 Sonnet 在 10 轮会话后零样本遵循率 13.41，加入显式提醒为 99.03，RAG 为 92.15，说明偏好被检索并明确提示即可大幅恢复遵循率。MemoryCode 中 GPT-4o 遵循单条编码约定为 94.5，长历史下降到 30.5；只输入指令链也出现类似下降，作者认为难点在于同时组合多条约定，RAG 对长历史无增益。MemoryArena 团体旅行任务把偏好作为相互依赖的规划约束，所有方法 SR=0，长上下文的 sPS（论文中的部分完成度得分）为 0.44–0.62，Mem0 为 0.24，Letta 为 0.35。

产品中把纠正转为可执行产物的路径有：Claude Code 在纠正对象为可重复步骤时同步改写对应 skill 文件（功能开关控制）；Cline `/newrule` 与 Cursor 从会话生成规则文件。

### 6.10 与经验记忆的差异

偏好与纠正类记忆以用户消息 span 与用户改写为证据，不依赖成败标签，每会话只有 0 至数条但单条即可能有高价值；作用域主键为用户加仓库、数据库或工作区；内容为"行为约束 + 原话 + 原因 + 适用条件"；执行方式为小体量常驻注入或编译为校验；主要风险是一次性请求被升格、过度个性化与第三方内容被当作用户偏好。经验记忆以工具 span 与 trace 级 outcome 为证据，需多条轨迹聚合，按任务簇或仓库组织，按任务检索注入，主要风险是错误经验传播与环境变化后失效。两者有交叉：失败报告更适合作为经验记忆的结果信号；针对可重复流程的纠正（如"提交前先跑 lint"）既是偏好，也可写入流程或 skill。

### 6.11 结论与倾向

1. 带具体内容的纠正与显式偏好可直接抽取；中断、拒绝、重述只说明上一步不被接受，单独使用精度最低，需与前序 agent 动作和后续用户消息配对。确定性标记先于 LLM 分类处理，置信度宜用可计数的证据（来源类型、独立会话数、最近反向证据），模型自报置信度无区分力（2407.10944）。
2. 一次性主张被写成偏好会传播并造成失败（PASB 观察分组 71.9% 对 45.0%），且写入时三分之一丢失来源。调研倾向于把"保留原话、来源与适用条件"和 Codex v2 式的措辞校准作为偏好条目的基本要求，并把"表述为默认或跨任务复现"作为个人偏好的升格条件。
3. 共享作用域的偏好与口径在产品中多数经有权限者确认后生效（Genie、Cortex Analyst、Hex、ThoughtSpot），或经证据累积后激活（Bugbot、Augment）；Hex 的"2 个用户、2 次会话、3 个来源"是检索到的唯一公开数值门槛。
4. 偏好的收益取决于执行方式。TRACE 的编译校验比注入高 15 个百分点；可确定性判定的偏好（禁用命令、文件命名、必跑检查、SQL 方言）适合编译为工具调用前后的检查。
5. 偏好撤销需要在检索与执行层生效。只在存储层标记失效或只追加新条目，模型仍会沿用旧值（TEPA、2608.25553、HorizonBench）。
6. 开放问题：项目级与组织级作用域缺少研究；data agent 偏好缺少真实数据与基准；从隐式编辑推断偏好的研究停留在写作任务，尚无代码或 SQL 产物上的实证。

## 7. data agent 的经验记忆

data agent 指执行 text-to-SQL、数据分析、数据科学建模与数据处理任务的 agent。与 code agent 相比，它的产物（SQL 结果集、数值答案）通常可以直接执行验证，记忆的作用域绑定数据库、schema 或语义模型。本节整理研究、产品、记忆类型差异、查询日志挖掘、验证门控证据、数据集与评测。

### 7.2 text-to-SQL

**Tk-Boost（2602.13521）**。把"部落知识"定义为纠正 agent 对数据库误解的知识。LLM 对错误 SQL 逐子句编辑直到结果与 gold 等价，每次编辑附一句说明；第二遍自反思剪除不必要的编辑；保留的编辑再写成去具体化的知识陈述与适用条件。适用条件覆盖 SQL 关键字、表、列、数据类型四类特征。误解分数据选择（"按自然年过滤时用日期列，不用财年属性"）与数据使用（"窗口函数先在全区间计算再过滤"）两类，由解析器比较两条 SQL 的表列集合自动判定。使用时把 agent 初稿按 CTE 切分，逐个 CTE 匹配条件。经验集取各数据集随机 25%。同条件下 NL-SQL 对记忆约 +3.9%–4.5%，朴素知识约 +4.7%–5.8%；内容消融从基线 27.7% 依次为 NL-SQL 对 32.7%、朴素知识 36.7%、非原子纠错 39.8%、未去具体化 41.6%、完整方法 44.6%。GPT-4.1 / SQLite 上修好 18.1% 的错误答案、改坏 1.2% 的正确答案，延迟 29.6 s→37.0 s。

**Crystallization（2608.07213）**。研究测试时修复产生的证据能否转为后续问题可复用的记忆。记忆来自首答失败问题的修复回合（预算 3 次），卡片只有通过验证门控才入库；基准实验中验证门控使用 oracle 正确性位，写卡片的模型看不到 gold SQL。每个数据库一个卡片库，按问题余弦相似度检索 top-5。BIRD dev（1,534 题、11 库、每库 70/30 划分、3 个种子）、Qwen3.5-27B 上，最简单的卡片格式（原问题 + 修正 SQL）使留出首答准确率（第一次作答即正确的比例）62.04%→66.38%（+4.34 个百分点，CI [+1.50, +7.49]），结晶率（迁移增益与按需修复上限增益之比）44.4%。其他结果：原题重放 96.1%，去掉本题卡片后 56.0%；本库卡片比同样有效的外库卡片高 6.73 个百分点；验证门控贡献 4.85 个百分点，不加门控的自投票卡片库比无记忆低 2.03 个百分点；检索 10 张比 1 张高 3.18 个百分点；完整修复轨迹、结构化 diff、失败标签、守卫条件、LLM 摘要等更丰富的格式比最简格式低 1.3–2.0 个百分点（差异不显著）。

**JPMorganChase 持续学习（2511.10674）**。持有 gold SQL 的 GPT-4o 扮演专家，学习者 SQL 结果错误时给出自然语言反馈。记忆分 4 级：NL-SQL 对、提炼事实、子任务 SQL 片段、库事实；Procedural Agent 用三个向量库，检索 top-3、距离阈值 0.28，每题至多存 5 条。BIRD dev 新题上 NP-0 由 34.1 升至 47.0，P-3 由 32.4 升至 51.3；只加提炼事实而不加过程化推理时下降到 43.7。

**AgentSM（2601.15709）**。记忆为执行轨迹，含按库合成的问题轨迹，合成问题的答案不判对错，保留其探索价值。按正则把步骤分为探索、执行、验证三阶段分别存为 Markdown，检索限定同库；高频共现的工具序列在支持度超过阈值时合并为组合工具。Spider 2.0-Lite（547 题）EX 28.7→44.8，步数 18.9→16.4（两者底座模型不同：Claude 3.7 与 Claude 4）；75 题消融中去掉轨迹阅读 EX 52.0→17.3；20 题格式对比中原始日志 25%、Markdown 或 JSON 50%。原文存在两处数字不一致：摘要与《生成方法调研》第 4.3 节对 25% 与 35% 的归属相反；错误分析中的 245/547 与 44.8% 的 EX 不符。

**MERIT 两篇同名工作**。2606.00547（UIC / Snowflake）面向交互式 text-to-SQL：回合级以请求 embedding 为键，值含完整轨迹、用户澄清、结果标签、策略 insight；轮次级以状态签名为键，值为 SQL 骨架等抽象动作；PPO 训练的 Qwen3-4B 选择器从 10 个候选中至多注入 1 条；BIRD-Interact 成功率 23.33%→33.01%（最佳基线 MemRL 29.00%），迁移到 Spider2-Snow 66.00%→69.29%。2608.05906 面向 agent 修复：用确定性失败类型分类组织正负两类修复记忆，只检索已结束 episode，Spider 66.34→69.79、BIRD 47.35→48.44，与无类型检索的差异不显著（据摘要）。

**其他**。LPE-SQL 维护正确本与错题本；MAGIC 用 manager、correction、feedback 三个 agent 从训练集失败中迭代生成自纠错指南；LSE 用 RL 训练模型按已见问题的反馈编辑自身上下文（三者据摘要）。ReFoRCE（2502.00675，Spider 2.0-Snow 35.83、Lite 36.56）只在单任务内做 schema 压缩、列探索与自修正，无跨任务记忆（据摘要）。

### 7.3 数据分析与数据科学

**DS-Agent（2402.17453）** 采用案例推理（CBR）。开发期案例库来自 12 个 Kaggle 竞赛前十名的技术报告与高分 notebook；检索按任务描述余弦相似度取 top-k，再由 LLM 结合前一次执行反馈重排；性能提升才把（任务描述，脚本）写回案例库。部署期只检索 1 个最相似案例，作者报告放入多个案例会互相干扰。部署期 one-pass 成功率 GPT-3.5 85%、GPT-4 99%（最佳基线 56%/60%）。

**DSMentor（2505.14163）** 的在线记忆条目为（题目，生成代码，正误标签），正确与错误都保留，任务按估计难度由易到难排序。保留错误样例的增益：QRData 0.475→0.508、LeetCode 0.733→0.792；课程顺序优于随机或由难到易。

**NVIDIA Data Explorer**（DABstep 第一，2026-03，官方博客）。离线学习阶段由强模型在 dev 任务上对照 gold 求解，把逐题脚本合并为跨题通用的 `helper.py` 函数库，函数在关联任务上测试失败即修订；离线反思比较相似问题解法的一致性，把模式、边界情况与易错点写入推理系统提示。Haiku 4.5 加该方案 Hard 89.95，Claude Code + Opus 4.5 从零求解为 66.93；未给出学习环节的单独消融。

**其他**。Data Interpreter（2402.18679）摘要提到 experience recording，机制未核对；ML-Master 2.0 用多层缓存把执行轨迹蒸馏为跨任务 insight；Tapilot-Crossing 的 AIR（2403.05307）从成功交互历史自生成反思，相对提升至多 44.5%；Persistent Discovery Context（2609.02129）让 data agent 复用此前发现的"意图 → 数据对象"映射（均据摘要）。ETL 与数据清洗方向未见跨会话的规则记忆代表工作。

性质差异有五点：

1. 作用域绑定数据对象。Crystallization 中本库卡片比同等有效的外库卡片高 6.73 个百分点，作者把库特有内容认定为主要增益来源；AgentSM、Crystallization、BIRD-History 的检索都限定同库。
2. 结果可由执行直接验证，验证门控本身就是增益来源（第 7.7 节）。
3. 时效受 schema 演化约束。表重命名、新增列、部分回填会让记忆失效；Continual Learning Bench（2606.05661）在第 20 题后在线迁移 schema 专门测试这一点。
4. 事实与偏好混杂。同一条口径既可能是组织规则，也可能是个人习惯（第 6.5 节）。
5. 治理要求更高。指标口径错误直接产出错误业务数字。

### 7.6 查询日志挖掘的相关做法

数据库领域从查询日志中挖掘可复用知识已有较长积累，代表工作（BIRD-History、MotherDuck 列描述、Beyond the Harness、Uber QueryGPT、QueryBot5000 与 Snowflake 查询哈希、Auto-Validate-by-History）的机制与数字见《生成方法调研》第 7.7 节。

这些工作说明：成功执行的最终查询是主要选样信号；子句级拆分与参数化模板是 SQL 侧的归一化手段；生产库上的增益明显大于公开基准；小模型可能因加入描述而退化；针对 schema 变更的失效机制在公开资料中少见。BIRD-History 只保留成功的最终查询，不含失败尝试与会话噪声，与 agent trace 的输入形态仍有差距。

| 在线写入、离线测试 | JPMC | 有反馈阶段写记忆，无反馈阶段测新题 | EX、错误类型分布 |
| 交互式 + 跨基准迁移 | MERIT（2606.00547） | 只在 BIRD-Interact 上训练选择器，迁移到 Spider2-Snow | 成功率、平均轮数 |
| 有状态 vs 无状态 + schema 漂移 | Continual Learning Bench（2606.05661） | 商品库 10 表、40 题，第 20 题后迁移 schema | 有状态与无状态增益：六任务平均 Mem0 20.2%、ACE 8.6%；数据库任务上 Claude Code 增益 43.6%；朴素 ICL 优于专用记忆系统 |
| 轨迹记忆问答 | AMA-Bench（2602.22769） | Spider2 轨迹上的记忆 QA 与端到端任务 | 端到端：AMA-Agent 26.2、长上下文 23.5、Mem0 15.6 |
| 开发期 / 部署期 | DS-Agent | 开发期积累案例，部署期换任务复用 | 成功率、one-pass 率、成本 |
| 产品内评测 | Databricks Genie benchmarks | 问题 + 期望 SQL 结果比对，benchmark 不进入上下文 | 准确率随时间变化 |

### 7.10 结论与倾向

1. data agent 记忆的强信号是"执行结果与参照一致"，参照可以是 gold、用户确认或独立验证器。验证门控的贡献已被量化（4.85 个百分点，不门控低于无记忆），自评信号会在记忆闭环中放大误判（被信任错误比例单次静态估计为 0.28，闭环中为 0.42），执行侧的答案无关信号可有效去偏。
2. "失败后修复成功"的回合信息量最高，同一回合可产出纠错知识（Tk-Boost 形态）与已验证查询（Crystallization 形态）。最简单的"问题 + 修正 SQL"格式不劣于更丰富的格式。
3. 记忆以数据库或语义模型为作用域边界，库特有内容是主要增益来源；schema 演化下的失效是公开研究中最薄弱的环节，Continual Learning Bench 是唯一设置，且结论为专用记忆系统不如朴素 ICL。
4. 口径与业务规则类记忆在产品中均经人工审核后生效，调研倾向于把这类条目与可自动生效的经验分开处理。
5. 开放问题：缺少带真实用户纠正的 data agent 轨迹；指标口径与业务术语类记忆缺少公开评测；产品侧未公开记忆收益数字；公开基准的标注错误率较高，评测需计入标签误差。
